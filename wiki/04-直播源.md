## ⚠️ 核心教训：测速 ≠ 测内容

**速度 9MB/s 的源可能是假信号**。真实案例：

`hebtv.com/jishi/cp1.m3u8`（列表里标 CCTV-13）实际是**冀时 APP 的 TVU 直播车回传备播卡**——花屏网格 + "TVU Networks" logo + Source/Receiver ID + 时间码。直播车不开机时云端就一直发这个。

推到电视上 = 用户看到花屏测试卡。

### 正确的验证方法：抓帧看画面

```bash
FF=~/.hermes/tools/ffmpeg-9.0.1-darwin-arm64/ffmpeg
"$FF" -y -hide_banner -loglevel error -i "$URL" -ss 4 -frames:v 1 frame.jpg
```
然后看图（人眼或 vision_analyze）：要确认**台标正确 + 是节目画面而非测试卡/彩条/占位**。

## ⚠️ 通道号错位

地方运营商服务器（txiptv 系）的通道号**不保证与频道号一致**：
- `125.125.236.31:9901` 上 `0010_1` 是 **CCTV-10**（不是 CCTV-9），真 CCTV-9 是 `0009_1`
- 换新源后必须重新抓帧验台标，不能信文件名

## 带过 token 的源会过期

`mgtv.com`（湖南）、`?_upt=`（哈尔滨）等带签名参数的源有效期短，过期后 403。频道表里已剔除这类主力源；保留的偶尔失效属正常，多源切换解决。

## 源格式速查

- `*.m3u8`（HLS）：乐播直接支持，首选
- 裸 `*.ts` / `udp://` / `rtp://` 组播：乐播不支持组播；单播 ts 走 Mac ffmpeg 转 HLS 才能播
- `txiptv` 风格：`http://IP:PORT/tsfile/live/NNNN_1.m3u8?key=txiptv&playlive=1&authid=0`，运营商串流服务器，量大管饱但随时会死

## ffmpeg 细节（这台 Mac 的特殊配置）

- ffmpeg 二进制：`~/.hermes/tools/ffmpeg-9.0.1-darwin-arm64/ffmpeg`（自编译，**无系统 CA**）
- 对 https 源报 `certificate verify failed`（curl 正常）→ 解法：**用 http 明文替代**（多数国内源 80 端口开放）或 curl 中转
- `-tls_verify 0` 不是合法输入选项（会 "Option not found" 直接退出）——别用
- 输出到已存在文件必须加 `-y`，否则交互式询问导致挂死
