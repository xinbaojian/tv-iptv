# 08 - 页面功能与云端部署

页面（PAGE 字符串）与后台任务的 设计要点、部署形态分析、开源脱敏流程。2026-10-13 页面功能迭代后沉淀。

## 页面功能与后台任务对应关系

| 页面按钮 | 后台类 | 做什么 | 状态查询 |
|---|---|---|---|
| 🔄 刷新源 | `Refresher` | 并发(4)重测已有源可用性 → 失效源后移 → 写回 channels.json | `/api/status` 的 `refresh` 字段 |
| ⬇ 拉源 | `SourcePuller` | 拉 REMOTE_LISTS → 去重 → name_key 匹配 → 候选测活 → 追加(上限8条/频道) → 写回 | `/api/status` 的 `pull` 字段 |
| ⚙ 设置 | `save_settings()` | 校验 → 更新全局 → 写 config.json → 后台 `TV()` 重连 | `/api/settings` 读取 |
| 源仓库筛选 | `SourcePuller.preview/add_channel` | 关键字分组预览 / 按名测活新增频道 | 同步返回 |

设计约定：

- 后台任务一律 **running/done/total/result 状态快照** 挂在 `/api/status` 上，页面 2.5s 轮询驱动按钮文案（"刷新中 37/104"）
- 刷新源**跳过正在播的频道**（避免换掉当前源）；拉源合并只追加不删除
- 前台乐观更新（`mode=starting`）+ 后台线程确认，是刻意设计——遥控器不能卡 30 秒

## 配置优先级与持久化

```
FFMPEG: 环境变量 > config.json > DEFAULTS
TV_IP/MAC_IP/PROXY: config.json > DEFAULTS
```

- config.json / channels.json 首启自动按默认值生成；损坏则回退默认并打日志
- 设置保存 = 校验（IP 正则、代理前缀、非空）→ 更新全局 → 落盘 → 后台重连电视
- 开源注意：DEFAULTS 只放占位值，真实配置在 gitignored 的 config.json（见下"脱敏流程"）

## 云端部署形态分析

核心约束：**服务必须能 TCP 访问电视的 DLNA 端口 (49152)**；中转模式额外要求电视能反拉服务 8899。

| 形态 | 做法 | 评价 |
|---|---|---|
| A. 家里常开设备 | 树莓派/NAS/旧笔记本跑 tv.py | ✅ 最稳，零公网暴露 |
| B. 云 + WireGuard/Tailscale 子网路由 | 家里隧道端把 192.168.1.0/24 路由进隧道，云服务跑主服务 | ✅ 可行；中转 HLS 地址要填电视可路由的 IP |
| C. 云 + frp 把 49152/8899 转发出去 | — | ⚠️ 电视控制口暴露公网，须加鉴权 |
| 纯公网云、无隧道 | — | ❌ NAT 穿不回去 |

代码层面两个天然兼容点：

- SSDP 组播不跨网段 → `find_tv()` 3 秒落空后**自动落到 `guess_tv_ctrl()` 单播猜 49152**，云上无需改代码
- 中转模式的 HLS 地址由 `MAC_IP` 全局变量拼出，改设置即生效

⚠️ **8899 无鉴权**：暴露公网前必须加 token 校验（未实现）；否则任何人可控制电视、蹭中转带宽。

## 适配电视（通用 DLNA 发现）

`find_tv()` 兼容任意品牌：M-SEARCH MediaRenderer v1+v2 → 只认设置 IP 的响应 → 解析设备 XML 的 `URLBase + controlURL`（坑 6 补斜杠必须保留）→ `friendlyName` 记日志 → **乐播(HappyCast/LEBO/乐播) 优先，其余 AVTransport 设备兜底**。

- 不支持 AirPlay / Chromecast / Miracast（屏幕镜像协议 ≠ 推链接）
- 个别品牌 DLNA 对 query URL、元数据要求不同，失败看 server.log
- 电视只在启动/保存设置时搜索一次；电视重开后重启服务或保存一次设置

## 开源脱敏流程（上传 GitHub 前必做）

1. `.gitignore` 收录全部本地数据：`config.json`、`channels.json`、`remote_sources/`、`hls_cache/`、`*.log`、`nohup.out`、`__pycache__/`
2. 代码内默认值（DEFAULTS）改为占位：IP 用 `192.168.1.x`，代理留空——**真实配置只活在本地 config.json**
3. 提供 `channels.example.json` / `config.example.json` 脱敏样例
4. 提交前按"入库文件口径"复扫：`grep -rln "敏感IP|用户名" --include="*.py" --include="*.md" --include="*.json"`（排除 gitignored 后应零命中）；`git check-ignore` 确认本地数据文件全被忽略
5. `git status` 无历史包袱时最省事；若历史里提交过敏感文件，需要 `git rm --cached` + 重写历史

实际案例：代理 IP（Tailscale 100.x 段）、家庭网段（192.168.1.x）只允许出现在 gitignored 的本地数据里；wiki 等文档中的 IPTV 聚合源站地址属社区公开基础设施，保留。

## 部署实战记录（2026-10-13，A+B 混合形态）

- **服务端**：家里 Linux 主机 `/opt/tv-iptv`，systemd 单元 `tv-iptv.service`（WorkingDirectory 决定 server.log 位置），`systemctl enable --now`；防火墙放行 8899/tcp（局域网 + tailscale0 都要能到）
- **config.json**：`TV_IP`=电视 IP；`MAC_IP`=家里主机局域网 IP（对电视可见，中转 HLS 用）——从别的机器迁移部署后第一件事就是改它
- **公网入口**：云服务器 nginx 反代 `iptv.<域名>` → `http://<home-tailscale-ip>:8899`，走 tailscale 内网；证书 `ym <子域名> new|install`（acme.sh 自动续期）
- **防护**：`auth_basic` 复用统一 htpasswd 文件（与其它子域同账号）；验证方式：无凭据/错凭据都应 401
- **迁移部署注意**：目标机无 rsync 时用 `tar czf - --exclude ... . | ssh host 'tar xzf - -C /opt/...'`；macOS bsdtar 打的包 GNU tar 解压会刷 xattr 警告，无害
- **无 ffmpeg 的主机**：直连模式完全可用，兜底中转会失败（`[中转失败]`）——需要中转就装 ffmpeg 并把 config.json 的 FFMPEG 指过去

### ffmpeg 安装（Rocky 9 实录）

- dnf 基础源无 ffmpeg；EPEL + RPM Fusion(TUNA) 路线死在依赖冲突（`nothing provides ladspa needed by rubberband`），且 TUNA 镜像下载极慢
- **生效方案**：静态单文件——`curl -x <代理> -L johnvansickle.com/ffmpeg/releases/ffmpeg-release-amd64-static.tar.xz`（约 40MB，走 config.json 的 PROXY），解压把 `ffmpeg` 放 `/usr/local/bin/`（systemd 默认 PATH 包含它，服务无需改配置）
- 静态版零依赖、版本新（7.0.2），`node`/`ffmpeg` 这类工具在家用主机上优先走静态包而非折腾仓库
