# 07 - 源刷新指南

源会死。当频道大面积失效时按此流程刷新。

## 流程

### 1. 拉最新列表（需代理）

```bash
curl -sL -x http://代理(config.json PROXY) \
  "https://raw.githubusercontent.com/best-fan/iptv-sources/main/cn_all.m3u8" \
  -o /tmp/cn_all.m3u8
wc -l /tmp/cn_all.m3u8   # 应有几百行
```

备选源仓库：
- `https://iptv-org.github.io/iptv/countries/cn.m3u`（iptv-org，质量一般）
- best-fan 致谢链：mzky/checklist、ssili126/tv、hujingguang/ChinaIPTV

### 2. 测活（HTTP 200）

```python
import subprocess, concurrent.futures, re
raw = open("/tmp/cn_all.m3u8", encoding="utf-8", errors="replace").read()
lines = raw.splitlines()
entries = []
for i, l in enumerate(lines):
    if l.startswith("#EXTINF"):
        name = l.split(",")[-1].strip()
        url = lines[i+1].strip()
        if url.startswith("http"):
            entries.append((name, url))

def check(e):
    name, url = e
    r = subprocess.run(["curl","-s","-m","4","-o","/dev/null","-w","%{http_code}",url],
                       capture_output=True, text=True, timeout=6)
    return name, url, r.stdout == "200"

with concurrent.futures.ThreadPoolExecutor(30) as ex:
    alive = [r for r in ex.map(check, entries) if r[2]]
print(len(alive), "存活")
```

### 3. 测速（对 ts 分片，不是 m3u8！）

```python
import urllib.parse, subprocess
def seg_speed(url):
    r = subprocess.run(["curl","-sL","-m","5",url], capture_output=True, timeout=7)
    segs = [l for l in r.stdout.decode(errors="replace").splitlines()
            if l.strip() and not l.startswith("#")]
    if not segs: return 0
    seg = urllib.parse.urljoin(url, segs[-1])
    r2 = subprocess.run(["curl","-s","-m","6","-o","/dev/null","-w","%{speed_download}",seg],
                        capture_output=True, text=True, timeout=8)
    return float(r2.stdout or 0)
```
阈值：>0.2MB/s 可用，越高越好。

### 4. 抓帧验内容（防测试卡，必做！）

```bash
FF=~/.hermes/tools/ffmpeg-9.0.1-darwin-arm64/ffmpeg
"$FF" -y -hide_banner -loglevel error -i "$URL" -ss 4 -frames:v 1 /tmp/frame.jpg
```
人眼或 AI 看图确认：**台标正确 + 节目画面**（不是 TVU/彩条/占位）。
新源/没验证过的服务器尤其要验——通道号会错位（如 125.125.236.31 上 0010_1 是 CCTV-10 不是 CCTV-9）。
2026-10-13 实证：老表里也藏着错位源——山西卫视的 222.169.85.8 `0118_1` 帧验发现实为**内蒙古卫视**，已移除。同日 CCTV-2/山西/吉林 靠帧验换上 1080p 源（原源 720×576 4:3，电视上两侧黑边）。
另外 ffmpeg 已改用系统 PATH（默认 `ffmpeg`，环境变量 `FFMPEG` 可覆盖），示例里的 `~/.hermes/tools/...` 路径不再是默认。

### 5. 更新 tv.py 频道表

`CHANNELS` 结构（验证过的源排最前）：
```python
CHANNELS = [
    {"name": "频道名",
     "sources": [
         {"url": "http://...", "proxy": False},   # proxy: 兜底模式拉流是否走 7890
     ]},
]
```
注意 Python 布尔是 `True/False`（不是 JSON 的 true/false——生成代码时踩过）。

### 6. 重启验证

```bash
pkill -9 -f tv.py                      # 宽松匹配！
cd ~/workspace/python/tv-iptv && python3 tv.py
curl -s "http://127.0.0.1:8899/api/play/0?src=0"   # 试播
sleep 8 && curl -s http://127.0.0.1:8899/api/status # 应见 PLAYING
```

## 日常维护建议

- 单个台失效：遥控器点线路数字换源即可，不用刷新
- 大面积失效（多半是 112.123.243.37 / 125.125.236.31 这类运营商服务器整体下线）：走上面全流程
- 想加频道：在 cn_all.m3u8 里找名字 → 三步验证 → 按格式插入 CHANNELS
- 长期方案：把本流程写成 check_sources.py 自动化（未来工作）
